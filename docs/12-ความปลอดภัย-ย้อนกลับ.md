# ความปลอดภัย การสำรอง และการย้อนกลับ

## หลักประกัน 3 ชั้นของโปรแกรมนี้

| ชั้น | กลไก | ทำอะไร |
|---|---|---|
| 1 | `-DryRun` | เดินทุกขั้นตอนโดยไม่แตะระบบ ตรวจได้ก่อน apply |
| 2 | backup อัตโนมัติ | เขียน `backups/<เวลา>_apply-<โปรไฟล์>.json` ก่อนแก้อย่างแรก |
| 3 | `restore` | คืนค่าทุกอย่างตามลำดับย้อนกลับ + ลบ scheme ที่สร้าง + สลับ scheme เดิม |

  "BaseScheme": "381b4222-f694-41f0-9685-ff5bb260df2e",
  "TuneScheme": "9a3f... ",
  "Tweaks": [
    {
      "Id": "power.cpu.min50",
      "Type": "Power",

จุดสำคัญ: `Previous.Exists = false` หมายถึงค่าเดิม **ไม่มีอยู่** — restore จะลบค่านั้นออก ไม่ใช่ตั้งเป็น 0

## สิ่งที่ restore ทำได้และทำไม่ได้

| ประเภท | restore อัตโนมัติ | หมายเหตุ |
|---|---|---|
| Power settings | ✅ | คืนค่า AC/DC ตามที่บันทึก |
| Registry (รวมค่าที่เดิมไม่มี) | ✅ | ลบค่าที่เดิมไม่มีให้ |
| Services (startup type + start) | ✅ | คืนค่าและ start ถ้าเดิมทำงานอยู่ |
| power scheme | ✅ | สลับกลับ + ลบ scheme ที่สร้าง |
| `fsutil` (last access, 8dot3) | ❌ | รายงาน `SKIP` — ต้องคืนเอง |
| `netsh` (TCP global) | ❌ | ตั้งค่ามาตรฐานคืนให้ แต่ไม่ใช่ค่าเดิมเป๊ะ |
| `bcdedit` (dynamictick, platformclock) | ❌ | ต้อง `bcdedit /deletevalue` เอง |
| ScheduledDefrag task | ❌ | `RevertScript` มีอยู่ แต่ restore ไม่เรียกใช้ (ดูด้านล่าง) |
| MMCSS tasks | ❌ | คืนค่าเดิมได้ถ้า backup มี (แต่ตอนนี้รายงาน SKIP) |

> **ทำไม**: tweaks ประเภท Script ให้ผลลัพธ์ที่ไม่สามารถอ่านกลับมาเปรียบเทียบเป็นค่าเดียวได้ (เช่น netsh คืนข้อความหลายบรรทัด) การ restore จึงเลือกที่จะไม่แตะและบอกผู้ใช้ตรง ๆ ดีกว่าเดาแล้วทำให้แย่ลง

### วิธีคืนค่า Script tweaks ด้วยมือ

```powershell
# fsutil
fsutil behavior set disablelastaccess 2      # กลับเป็น default (อัปเดตตามการเข้าถึง)
fsutil behavior set disable8dot3 2           # กลับเป็น per-volume

# netsh
netsh int tcp set global autotuninglevel=normal
netsh int tcp set global rss=enabled
netsh int tcp set global timestamps=disabled
netsh int tcp set global ecn=default

# bcdedit
bcdedit /deletevalue disabledynamictick
bcdedit /deletevalue useplatformclock

# scheduled task
Enable-ScheduledTask -TaskName ScheduledDefrag

# power (hibernate)
powercfg -h on
```

## กู้คืนเมื่อเครื่องมีปัญหา

### กรณีที่ 1: ระบบยังบูตได้ แต่พฤติกรรมแปลก

```powershell
.\Level51Tune.ps1 restore
```

ถ้าลืมว่า backup ไฟล์ไหน:

```powershell
Get-ChildItem .\backups\*_apply-*.json | Sort-Object LastWriteTime -Descending |
  Select-Object -First 5 Name, LastWriteTime
```

### กรณีที่ 2: บูตช้า/ค้างหลังแก้ bcdedit

1. บูตเข้า **Safe Mode** (กด Shift ค้างตอนกด Restart → Troubleshoot → Advanced → Startup Settings → Safe Mode)
2. เปิด Command Prompt (Admin)
3. `bcdedit /deletevalue disabledynamictick` และ `bcdedit /deletevalue useplatformclock`
4. รีบูตปกติ

หรือใช้ **System Restore** (`rstrui.exe`) ย้อนไปจุดก่อนหน้า

### กรณีที่ 3: power scheme เสียหายทั้งหมด

```powershell
# คืนค่า scheme มาตรฐานของ Windows (ไม่ลบ scheme ที่สร้างเอง)
powercfg -restoredefaultschemes
```

⚠️ คำสั่งนี้ลบ power plan ที่ผู้ใช้สร้าง**ทั้งหมด** รวม `LEVEL51 Ultimate Performance` และ `GameTurbo` ของคุณ — ใช้เป็นทางเลือกสุดท้าย

### กรณีที่ 4: บริการที่ปิดทำให้ Windows ทำงานผิดปกติ

```powershell
# เปิดบริการกลับเป็น Manual (ค่า default ของส่วนใหญ่)
foreach ($s in 'SysMain','WSearch','DiagTrack','dmwappushservice','MapsBroker') {
  Set-Service -Name $s -StartupType Manual -ErrorAction SilentlyContinue
  Start-Service -Name $s -ErrorAction SilentlyContinue
}
```

### กรณีที่ 5: registry ผิดปกติ

- ใช้ `System Restore` (จะคืน registry snapshot)
- หรือใช้ `reg export`/`reg import` ถ้าสำรองไว้
- **อย่า** แก้ registry ด้วยมือถ้าไม่แน่ใจ — `HKLM\SYSTEM` ผิดพลาดอาจทำให้บูตไม่ขึ้น

## Checklist ก่อน apply ครั้งแรก

```
[ ] อ่าน docs/04-โปรไฟล์.md แล้วเลือกโปรไฟล์ที่ตรงกับงาน
[ ] รัน bench -Label before และบันทึกผล
[ ] รัน apply -DryRun และอ่านทุกรายการ
[ ] รู้ว่าต้อง reboot หรือไม่ (มี tweak ที่ Reboot = จริง)
[ ] ปิดโปรแกรมที่จัดการพลังงานเอง (Control Center, ThrottleStop, XTU)
[ ] มีไฟล์สำคัญสำรองไว้
[ ] รู้วิธีเข้าถึง Safe Mode
[ ] รู้คำสั่ง restore
```

## Checklist หลัง apply

```
[ ] รัน status — ไม่มีอะไรผิดปกติ
[ ] รัน audit -Profile <ชื่อ> — ตรวจว่า OK ตามที่ควร
[ ] ใช้งานปกติ 30 นาที — ไม่มีอาการแปลก
[ ] เล่นเกม/ทำงานหนัก 15 นาที — ดูอุณหภูมิและ frametime
[ ] bench -Label after แล้ว compare
[ ] ถ้าไม่พอใจ → restore
```

## ระดับความเสี่ยงและผลกระทบที่อาจเกิดขึ้น

| Tweak | ถ้าผิดพลาดจะเป็นอย่างไร | ความสามารถกู้คืน |
|---|---|---|
| power settings | เครื่องร้อน/ช้า | 100% (restore) |
| registry HKCU | UI เปลี่ยน, ฟีเจอร์หาย | 100% (restore) |
| registry HKLM | ไดรเวอร์/ฟีเจอร์บางตัวไม่ทำงาน | 100% (restore) + reboot |
| services | ฟีเจอร์บางอย่างเสีย | 100% (restore) |
| fsutil/netsh | IO/เครือข่ายเปลี่ยนพฤติกรรม | ทำมือได้ 100% |
| bcdedit | บูตช้า/ค้าง | Safe Mode + deletevalue |
| DisableDynamicPstate | GPU ร้อนตลอด | restore + reboot |
| IDLEDISABLE | เครื่องร้อน idle | restore |

## ข้อควรระวังเฉพาะเครื่องนี้

1. **อย่า apply `max` แล้วปิดเครื่องทันที** — scheme ใหม่จะยัง active อยู่ตอนบูตครั้งถัดไป ต้องรอให้แน่ใจว่าเครื่องเสถียรก่อน
2. **Windows Update อาจรีเซ็ต registry บางค่า** — audit หลังอัปเดตใหญ่ทุกครั้ง
3. **อย่าใช้หลายเครื่องมือพร้อมกัน** — ThrottleStop + Level51Tune + Control Center อาจเขียนทับกันจนหาสาเหตุไม่ได้
4. **Fast Startup ปิดอยู่หรือไม่** — ถ้าเปิด (default) การ shutdown จะไม่รีเซ็ตไดรเวอร์จริง ทำให้ tweak ที่ "ต้อง reboot" อาจไม่ทำงานจนกว่าจะ restart จริง

## การเก็บ backup ระยะยาว

`backups/` ถูก gitignore ไว้ (ไม่ขึ้น GitHub) จึงควร:

- คัดลอกโฟลเดอร์ `backups/` ไปเก็บที่อื่นเป็นระยะ
- หรือรัน `report` เก็บไว้เป็นหลักฐานสถานะ
- เก็บไฟล์ `state/last.json` ไว้ด้วยถ้าอยากรู้ว่าล่าสุดทำอะไร

## สรุป

1. `-DryRun` ฟรีและปลอดภัย — ใช้ทุกครั้งก่อน apply
2. backup ถูกสร้างอัตโนมัติ ไม่ต้องสั่งเอง
3. `restore` คืนได้ 100% สำหรับ power/registry/services
4. Script tweaks ต้องคืนเอง — เอกสารนี้บอกคำสั่งครบ
5. รู้ทางออก (Safe Mode, System Restore, powercfg -restoredefaultschemes) ก่อนเริ่ม
