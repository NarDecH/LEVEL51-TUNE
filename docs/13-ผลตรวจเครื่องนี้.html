ค่าตีความ

24 W GPU ตอน idleค่อนข้างสูง ปกติควร 8-15 W — ควรตรวจว่ามีโปรเซสใช้ GPU อยู่

5. ข้อค้นพบและสิ่งที่ควรทำ (เรียงตามความคุ้มค่า)

1) แรมเป็น single channel — โอกาสที่ใหญ่ที่สุด

พบแรมเพียง 1 แท่ง (ChannelA-DIMM0 32 GB @ 3200 MT/s) ทำให้ memory bandwidth เหลือครึ่งเดียวของ i9-9900K ที่รองรับ dual channel

  • ผลกระทบ: เกมที่กิน bandwidth (open world, simulation), การเรนเดอร์, VM, การบีบอัด/แตกไฟล์
  • ทางแก้: เพิ่มแรม 32 GB แท่งที่สองที่สเปกเดียวกัน (JM3200HSE-32G หรือเทียบเท่า)
  • คาดว่าจะได้ memory copy ~8,000-10,000 MB/s (วัดด้วย bench เทียบกันได้)

นี่คือการปรับปรุงที่คุ้มที่สุดและไม่มีค่าปรับด้านความร้อน ซึ่ง tweak ซอฟต์แวร์ทั้งหมดในโปรเจกต์นี้ทำแทนไม่ได้

2) ค่าซีพียูขั้นสูงถูกซ่อน

PERFBOOSTMODE / CPMINCORES / PERFEPP อ่านไม่ได้ → ต้องปลดซ่อนก่อน ไม่งั้น tweaks ของ CPU บางตัวจะขึ้น WARN

.\Level51Tune.ps1 apply -Profile performance    # มี win.unhide-power-settings

3) ค่าเริ่มต้นยังเป็นของ Windows ทั้งหมด

HAGS ปิด, GameDVR เปิด, Game Mode ปิด — เป็นของฟรีที่ได้ผลทันทีโดยไม่ต้องแลกอะไร

.\Level51Tune.ps1 apply -Profile balanced

4) GPU กินไฟ 24 W ตอน idle

ปกติ GTX 1060 ในโน้ตบุ๊กตอน idle ควรอยู่ที่ 8-15 W ถ้าค้างที่ ~24 W ให้ตรวจ:

nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
nvidia-smi -q -d PERFORMANCE

สาเหตุที่เป็นไปได้: โปรเซสที่ใช้ GPU ค้าง (เบราว์เซอร์, Wallpaper Engine, OBS), หรือไดรเวอร์ไม่ยอมลง P8 เพราะมีจอภายนอก/USB-C ต่ออยู่

5) มี power plan ที่ผู้ใช้สร้างเอง 3 ชุด

LEVEL51 Ultimate Performance, GameTurbo, Dynamic Boost Performance — โปรแกรมจะไม่แตะทั้งสามนี้ แต่ต้องระวังว่าถ้าคุณสลับไปใช้เองหลังจาก apply แล้ว audit จะขึ้น no ทั้งหมด (เพราะ scheme เปลี่ยน)

6) Disk write ต่ำกว่าสเปก

990 EVO Plus เป็น SSD PCIe 4.0 แต่แพลตฟอร์มนี้ (2019) รองรับ PCIe 3.0 เท่านั้น เพดานจึงอยู่ที่ ~3,500 MB/s ไม่ใช่ 7,250 — และตัวเลขจาก bench ต่ำกว่านั้นอีกเพราะนับ fsync ด้วย ถ้าต้องการเลข absolute ให้ใช้ CrystalDiskMark

7. ข้อจำกัดของการวัดชุดนี้

  • วัดครั้งเดียวต่อค่า (ไม่ใช่ median ของ 3 รอบ) — noise ±3-5%
  • เครื่องอยู่ในโหมด Balanced ไม่ใช่ performance จึงเป็น baseline ที่ถูกต้อง สำหรับการเทียบก่อน/หลัง apply
  • ตัวเลขดิสก์ขึ้นกับ page cache และ fsync จึงไม่ใช่คะแนน absolute
  • ไม่ได้วัด frametime ในเกม (ต้องใช้ PresentMon/CapFrameX) — bench วัด throughput ไม่ได้วัด latency
  • อุณหภูมิห้องและสภาพฝุ่นมีผลมากกว่าการตั้งค่าซอฟต์แวร์เกือบทั้งหมด

8. การตรวจซ้ำด้วยตัวเอง

.\Level51Tune.ps1 status
.\Level51Tune.ps1 audit -Profile performance
.\Level51Tune.ps1 bench -Label baseline -Seconds 4
.\Level51Tune.ps1 report -Path .\reports\level51-status.md

ผลจะถูกเก็บใน benchmarks/history.jsonl และ reports/ ซึ่งไม่อยู่ใน git (มีข้อมูลเฉพาะเครื่อง)

วิธีตีความ (สำคัญ)

  • CPU และ disk ไม่ต่างกันเลย (|delta| ≤ 0.3%) — โปรไฟล์นี้ไม่ได้เพิ่ม throughput และไม่ได้ลดลง
  • Memory +17.5% ไม่ควรถือว่าเป็นผลของ scheme — memory copy ขึ้นกับ uncore/ring clock และสภาพ cache มากกว่า power plan; รอบ B อยู่ตรงกลางลำดับ (ร้อน/ตื่นเต็มที่แล้ว) จึงมีแนวโน้มได้เปรียบจาก warm-up มากกว่าจากการตั้งค่า
  • การวัดแบบ A-B-B-A ลด order bias ได้แต่ไม่หมด — ถ้าต้องการข้อสรุปที่แน่นอนกว่านี้ ต้องรัน 5 รอบ/ฝั่งและใช้ median

สรุปที่ซื่อสัตย์

การปรับแต่งชุดนี้ ไม่ได้ทำให้ throughput เพิ่มขึ้นอย่างวัดได้ บนเครื่องนี้ เพราะ:

  1. ซีพียูถูกจำกัดด้วยความร้อน/พลังงานอยู่แล้ว (efficiency 83-85% ของ physical cores คือสภาวะปกติ ไม่ใช่ throttling รุนแรง)
  2. คอขวดใหญ่ที่สุดคือ แรม single channel ซึ่ง tweak ซอฟต์แวร์แตะไม่ได้
  3. สิ่งที่โปรไฟล์นี้เปลี่ยนคือ latency/jitter (core parking, ASPM, disk timeout, MMCSS, Nagle) ซึ่ง bench วัดไม่ได้ — ต้องใช้ LatencyMon หรือ frametime graph

ถ้าอยากได้ตัวเลขที่ยืนยันผลด้าน latency ให้วัด DPC latency ด้วย LatencyMon ก่อน/หลัง และดู Highest measured interrupt to process latency (ค่าที่ต่ำลงคือดีขึ้น)

ถ้าไม่ต้องการโปรไฟล์นี้ต่อ

.\Level51Tune.ps1 restore      # กลับไป Balanced ตาม backup ล่าสุด

หรือสลับเองใน Control Panel → Power Options → Balanced (scheme LEVEL51-TUNE performance จะยังอยู่ให้สลับกลับได้)

10. ภาคผนวก: วัด latency หลัง apply (DPC / interrupt)

รัน .\Level51Tune.ps1 latency -Seconds 15 บน scheme LEVEL51-TUNE performance (เครื่อง idle, ไม่มีงานหนักรันอยู่):

counterAvgMaxเกณฑ์
% DPC Time0.03%0.10%< 3%
% Interrupt Time0.17%0.39%< 1%
% Idle Time84.76%88.37%สูง = เครื่องว่างจริง
Context Switches/sec8,42610,582ยิ่งต่ำยิ่งดีเมื่อ idle

วิธีตีความ

  • DPC/interrupt ต่ำมาก (0.03% / 0.17%) → ไม่มีไดรเวอร์หรืออุปกรณ์ที่ก่อ jitter บนเครื่องนี้ คอขวดไม่ใช่ interrupt storm
  • ค่า % Idle Time 84% ยืนยันว่าการวัดทำตอนเครื่องว่างจริง ตัวเลข DPC จึงไม่ถูกเจือจางด้วยงานอื่น
  • ค่าเหล่านี้เป็น baseline หลัง apply เท่านั้น — การเทียบก่อน/หลังแบบสลับ scheme ต้องรัน tools\AB-Latency.ps1 แบบ Administrator (ยังไม่ได้รันในรอบนี้)
  • ถ้าต้องการ frametime จริงในเกม ต้องใช้ PresentMon/CapFrameX เพราะ performance counter ไม่ได้วัดเส้นทาง render

ข้อสรุปที่เกี่ยวข้อง

ผลรวมของหลักฐาน (throughput ไม่เปลี่ยน, memory +17.5% เป็น warm-up artifact, DPC ปกติ) ชี้ว่า โปรไฟล์ performance ไม่ได้ทำให้เครื่องเร็วขึ้น แต่ก็ไม่ได้ทำให้แย่ลง — สิ่งที่ได้คือค่าที่นิ่งขึ้นและ fitur ที่ปิดไป (core parking, ASPM, disk timeout, Nagle) ซึ่งช่วยเรื่อง jitter ในสถานการณ์จริงมากกว่าตัวเลข benchmark
