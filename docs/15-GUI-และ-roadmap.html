คำตอบสั้น

ได้ และทำเสร็จแล้วในรอบนี้ — โปรเจกต์มี Web GUI ที่ทำงานจริงอยู่ที่ Level51Tune.Web.ps1 (dashboard บน http://localhost:8730/) ซึ่งเรียก engine ตัวเดียวกับ CLI ทุกฟังก์ชัน: ดูสถานะ, audit, apply, dry-run, bench, latency, restore และ log

เหตุผลที่เลือก Web GUI เป็น GUI ตัวแรก ไม่ใช่ WPF/WinForms:

เหตุผลรายละเอียด
ไม่ต้องติดตั้งอะไรใช้ System.Net.HttpListener ที่มีใน .NET/Windows อยู่แล้ว ไม่มี node_modules, ไม่มี Electron 200 MB
หน้าตาควบคุมได้เต็มที่HTML/CSS ทำ responsive, dark theme, ฟอนต์ไทย ได้ในไฟล์เดียว
ทดสอบได้จริงเปิดในเบราว์เซอร์ ตรวจ DOM/network/console ได้ (WPF ตรวจยากกว่าและต้องมีจอ)
ใช้จากมือถือใน LAN ได้ถ้าต้องการเปลี่ยน bind address ได้ในอนาคต (ปัจจุบันล็อก loopback เพื่อความปลอดภัย)
ต่อยอดเป็น desktop app ได้ถ้าอยากได้ tray icon + auto-elevate ให้ห่อด้วย WPF ทีหลัง โดยไม่ต้องเขียน UI ใหม่

สถาปัตยกรรมที่ใช้ (และการแยกชั้น)

Level51Tune.psm1  ← engine (detect / backup / apply / restore / audit / bench / latency)
   ├── Level51Tune.ps1        CLI  (thin adapter: parse args → เรียก engine)
   ├── Level51Tune.Web.ps1    GUI  (thin adapter: HTTP → เรียก engine)
   │      └── src/WebUI.ps1   HTML dashboard (string เดียว, ไม่มี asset ภายนอก)
   └── tools/*.ps1            benchmark / A-B tester

หลักสำคัญ: GUI ไม่มี logic ของตัวเอง ทุกอย่างเรียกฟังก์ชันเดียวกับ CLI (Invoke-L51Apply, Invoke-L51Restore, Invoke-L51Audit, Invoke-L51Bench, Measure-L51Latency) ทำให้:

  • ไม่มีโอกาสที่ CLI กับ GUI ให้ผลไม่ตรงกัน
  • การเพิ่ม tweak ใหม่ปรากฏใน GUI ทันทีโดยไม่ต้องแก้ UI
  • test ที่มีอยู่ (23 เคส) ครอบคลุมทั้งสองทาง

ความปลอดภัยของ Web GUI

ออกแบบให้ปลอดภัยพอสำหรับเครื่องส่วนตัว และไม่เป็นช่องโหว่ใหม่:

มาตรการรายละเอียด
bind เฉพาะ loopbackhttp://localhost:8730/ เท่านั้น ไม่รับจากเครือข่าย
token สุ่มต่อ sessionสร้างตอนเริ่ม ออกใน URL ที่พิมพ์ใน console; ทุก API ต้องมี X-L51-Token
ไม่มี CORSไม่มี header Access-Control-Allow-Origin → หน้าจากเว็บอื่นเรียก API ไม่ได้
path traversal guard/docs/.. ถูก normalize และปฏิเสธ (ทดสอบแล้วได้ 404)
ไม่เก็บ credentialไม่มี password/token ลงดิสก์
admin เป็นของผู้ใช้ถ้าไม่ได้เปิดแบบ Administrator ปุ่ม apply จะได้ 403 พร้อมข้อความบอก

ข้อจำกัดที่ต้องรู้: token อยู่ใน URL (history/log ของเบราว์เซอร์อาจเก็บไว้) และไม่มี TLS เพราะเป็น loopback — ห้ามเปลี่ยนให้ bind 0.0.0.0 โดยไม่มี auth ที่แข็งแรงกว่านี้

ทางเลือกอื่นและเหตุผลที่ไม่เลือก (ตอนนี้)

ทางเลือกข้อดีข้อเสียเหมาะเมื่อ
WPF/WinForms ใน PowerShellnative, มี tray icon, เปิดได้ทันทีไม่ต้องมีเบราว์เซอร์XAML ยาว, ฟอนต์ไทยต้องตั้งเอง, ทดสอบอัตโนมัติยาก, ต้องมีจอต้องการ tray + auto-start + หน้าตาแบบแอปWindows
Web GUI (ที่ทำแล้ว)ไม่มี dependency, ทดสอบได้, ปรับ UI เร็วต้องเปิดเบราว์เซอร์, ไม่มี trayใช้เป็น GUI หลักระยะแรก
Electron/TauriUI สวย, ecosystem ใหญ่ต้องติดตั้ง build toolchain, ขนาดใหญ่, ซ้ำซ้อนกับ PowerShell engineเมื่อมีทีม frontend และต้องการแจกจ่ายเป็นแอป
.NET MAUI / WinUI 3native สมัยใหม่, cross-deviceต้องเขียน engine ใหม่เป็น C#, งานใหญ่เมื่อจะทำเป็นผลิตภัณฑ์จริงจัง
PowerShell + Terminal GUI (Spectre.Console)เร็ว, สวยใน terminalไม่ใช่ GUI จริง, ใช้เมาส์จำกัดผู้ใช้สาย CLI

Roadmap ที่แนะนำ

ระยะ 1 (เสร็จแล้วในรอบนี้)

  • engine + CLI + 60 tweaks + backup/restore + bench + latency
  • Web GUI: สถานะ, โปรไฟล์, dry-run, apply, audit, bench, latency, restore, log, ลิงก์เอกสาร
  • เอกสารไทย 15 บท + test 23 เคส

ระยะ 2 (เสร็จแล้ว)

  1. Start-LEVEL51.cmd — ดับเบิลคลิกเดียว ขอ UAC แล้วเปิด dashboard (ปิดช่องว่าง "ต้องพิมพ์ command")
  2. หน้า Settings ราย tweak — ค้นหา/กรองหมวด/เลือกตามโปรไฟล์/บันทึกเป็น state/custom.json แล้ว apply ได้ทั้ง GUI และ CLI (apply -Custom)
  3. กราฟ realtime 6 ตัว — CPU load, CPU clock, GPU temp, GPU power, RAM used, GPU clock (อัปเดตทุก 2 วินาที, เก็บ 60 จุด)
  4. ปุ่ม "วัด + เทียบกับครั้งก่อน" — รัน bench แล้วแสดง delta เทียบผลครั้งก่อนในคลิกเดียว

ระยะ 3

ระยะ 3 (เสร็จแล้ว)

  1. Tray app — Level51Tune.Tray.ps1 (WinForms NotifyIcon): เปิด Dashboard, สลับโปรไฟล์, ตรวจสถานะเป็น balloon, เปิด log/docs, ออก
  2. per-app GPU editor — แท็บ “GPU ต่อแอป” + CLI gpuprefs (เขียน HKCU\...\UserGpuPreferences)
  3. ประวัติ + rollback ทีละครั้ง — แท็บ “ประวัติ/ย้อนกลับ” อ่าน backups/ และ restore ไฟล์ที่เลือก + CLI history
  4. audit ราย tweak ในหน้า Settings — ปุ่ม “ตรวจสถานะที่เลือก” ใช้ Invoke-L51Audit -TweakIds

ระยะ 4

ระยะ 4 (บางส่วน)

  1. tools/Build-Package.ps1 — สร้าง dist/LEVEL51-TUNE-<version>.zip พร้อมใช้ (เสร็จแล้ว)
  2. หน้าตรวจอัปเดตเวอร์ชัน เสร็จแล้ว: CLI update + ปุ่ม “ตรวจอัปเดต” ใน GUI (อ่านเฉพาะ metadata ของ release/tag — repo มี release v1.0.6 พร้อมไฟล์ zip/msix แนบให้เทียบแล้ว)
  3. profile detection เสร็จแล้ว: recommend + การ์ด “คำแนะนำสำหรับเครื่องนี้” (เลือกโปรไฟล์ตาม RAM channel / CPU class / dGPU)
  4. code signing ทำไปป์ไลน์แล้ว: Build-Package.ps1 -CertificateThumbprint <thumb> ลงนามทุก .ps1/.psm1 ด้วย Authenticode — เหลือแค่ certificate ของผู้พัฒนา
  5. MSIX เสร็จแล้ว: tools/Build-Msix.ps1 คอมไพล์ launcher (C# ผ่าน csc.exe) + AppxManifest.xml + assets แล้ว pack ด้วย makeappx.exe → dist/LEVEL51-TUNE-<version>.msix
  6. MSIX — ผลตรวจครบวงจรบนเครื่องนี้: Build-Msix.ps1 -Unsigned → Add-AppxPackage -AllowUnsigned (Administrator) ได้ Status: Ok → เปิดจาก Start ด้วย AUMID NarDecH.LEVEL51TUNE_f8fxc7vhmgvhy!App แล้วเซิร์ฟเวอร์รันจาก C:\Program Files\WindowsApps\...\Level51Tune.Web.ps1 และ dashboard ตอบ 401 เมื่อไม่มี token → ถอนด้วย Remove-AppxPackage เรียบร้อย
  7. เงื่อนไขการติดตั้ง MSIX ที่ต้องรู้: แพ็กเกจ unsigned ต้องมี marker OID.2.25.311729368913984317654407730594956997722=1 ต่อท้าย Publisher (สคริปต์ใส่ให้เมื่อใช้ -Unsigned) · ต้องเปิด Developer Mode · และเพราะมี .exe ต้องติดตั้งด้วย PowerShell แบบ Administrator
  8. ข้อจำกัดที่คงอยู่ของ MSIX: รันใน container จึงขอ UAC ไม่ได้ (launcher เปิด dashboard แบบไม่ elevated; apply/restore ต้องใช้ Start-LEVEL51.cmd)
  9. MSIX — การลงนาม: Build-Msix.ps1 -PfxPath <file.pfx> -PfxPassword <...> เรียก signtool sign /fd SHA256 · ถ้าเพิ่ม -TimestampServer <url> จะต่อเน็ตเพื่อประทับเวลา (opt-in เท่านั้น — invariant 13) · ทดสอบบนเครื่องนี้ด้วย self-signed cert CN=LEVEL51-TUNE แล้วติดตั้งสำเร็จ — แต่สำหรับแจกจ่ายจริงยังต้องใช้ cert จาก CA ที่เชื่อถือได้

ข้อควรระวังในการทำ GUI ต่อ

  1. อย่าลอกจาก engine — GUI ต้องเรียกฟังก์ชันใน Level51Tune.psm1 เท่านั้น
  2. อย่าให้ UI ตัดสินใจเรื่องสิทธิ์ — ตรวจ admin ที่ engine เสมอ (Assert-L51Admin)
  3. ทุก action ที่แก้ระบบต้องมี confirm — ตอนนี้ apply/restore มี confirm() แล้ว
  4. อย่าเก็บ state ใน UI — อ่านจาก engine ทุกครั้ง (single source of truth)
  5. ทดสอบด้วย dry-run ก่อนเสมอ เมื่อเพิ่ม endpoint ใหม่

สรุป

  • ทำ GUI ได้ และทำแล้ว: Web GUI ทำงานจริง ตรวจด้วยเบราว์เซอร์แล้ว (สถานะ, dry-run 17 OK/1 SKIP, log)
  • จุดที่ควรลงทุนต่อไม่ใช่ "หน้าตา" แต่คือ ทางเข้า (one-click + UAC) และ การเห็นผล (กราฟ/ประวัติ) เพราะ engine ทำงานครบแล้ว
  • ถ้าต้องการแอป Windows แท้ ๆ ให้ห่อ Web GUI ด้วย WPF + WebView2 หรือทำ tray shell — ไม่ต้องเขียน engine ใหม่
